## Summary

A row delta with `validateFromSnapshot(s)` checks, on each attempt's
metadata, that `s` is an ancestor of the branch's head. When another
writer has expired `s`, or rolled the branch back past it, the check
fails with `IllegalArgumentException`, which reads as a bad argument
from the caller. The same conflict fails an overwrite with
`ValidationException`.

## Reproduction

```java
table.newFastAppend().appendFile(FILE_A).commit();
long read = table.currentSnapshot().snapshotId();
RowDelta delta = table.newRowDelta().addRows(FILE_B)
    .validateFromSnapshot(read).validateNoConflictingDataFiles();

Table other = catalog.loadTable(ID);
other.newFastAppend().appendFile(FILE_C).commit();
other.expireSnapshots().expireSnapshotId(read).commit();

delta.commit();
// IllegalArgumentException: Snapshot <read> is not an ancestor of <head>
```

## Cause

`BaseRowDelta.validate` checks the ancestry with `Preconditions`
([BaseRowDelta.java#L133-L140](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/BaseRowDelta.java#L133-L140)).
It runs on the metadata the attempt refreshed, so it reports what
changed since the call, not the call.

## Impact

A caller that tells conflicts (`ValidationException`, rerun the job)
from errors (`IllegalArgumentException`, fix the job) takes this
conflict for an error. Spark's row-level operations set the starting
snapshot, and a concurrent expiry of a snapshot a long-running MERGE
read is possible when retention is short. The table is unchanged.

## Fix

The same check, with `ValidationException.check` and the same message.

## Tests

`TestRowDelta.testValidateFromSnapshotExpiredConcurrently`, on format
versions 2 and later, on `main` and on a branch. All 6 cases fail
without the fix; with it, `TestRowDelta` and the full `iceberg-core`
test task pass.

## Before a PR

- **The nearest upstream cases.** [#17202](https://github.com/apache/iceberg/issues/17202) (open) reports a
  `rewrite_data_files` whose starting snapshot was expired concurrently.
  RussellSpitzer (member): "My read is that the current behavior is
  working as designed", though "I'm fine with a small improvement to the
  error path". Its fix, [#17204](https://github.com/apache/iceberg/pull/17204), closed by the stale bot unreviewed,
  made it an `IllegalStateException`. A rewrite tolerates the conflict
  and a row delta fails either way, so the question here is only which
  exception. [#18509](https://github.com/apache/iceberg/pull/18509) (open) is a Flink row delta that fails after an
  expiry with a `ValidationException`, "Cannot determine history between
  starting snapshot null and the last known ancestor"; pvary (member),
  2026-10-21: "Shall we just fix it in the core?"
- **Not A4.** fileio-catalog's A4 accepts the `IllegalArgumentException`
  that #16146 chose for a v2 position delete committed after a v3
  upgrade: there a test expects it. No test expects this one.

## In fileio-catalog

No workaround: no fuzzer sets a starting snapshot. The canary is
`TestIcebergCoreIssues.aRowDeltaFromAnExpiredSnapshotFailsValidation`.
It asserts only that the commit fails with a `ValidationException`.
