# C35. A transaction retried after a conflict counts its delete files twice in the snapshot summary

| **Fix** | `core-fixes` [`25bebf2`](https://github.com/cdouglas/iceberg/commit/25bebf2c0b), "Core: Count a transaction's retried delete files once in its summary": #17986's `MergingSnapshotProducer` change, with a test of the transaction's path. |
| **Found by** | fileio-catalog's rebase oracle, calibration p22-cal-unmergeable (2026-11-20): R a table transaction (an overwrite, then an equality delete) raced by a branch's create; its reference, Iceberg's `BaseTransaction` retry, summarized the delete snapshot with two added delete files where it added one, and the subject (which merged R's record) with one. |

## Summary

A row delta, or any `MergingSnapshotProducer` that adds delete files,
adds each new delete file to its summary (`addedDeleteFilesSummary`) as it
writes the delete manifests, and keeps the manifests it wrote
(`cachedNewDeleteManifests`) for the next `apply`. It cleared the summary
only when it invalidated that cache itself (new delete files added since).

A commit into a transaction is a commit too: `SnapshotProducer.commit`
then cleans up the manifests the committed snapshot does not keep
(`cleanUncommitted`), and with them empties the cache. On a table that
merges manifests, the new delete manifest is merged into another, so it is
not kept, and the cache is emptied. When the transaction's commit then
fails its precondition (another writer committed), `BaseTransaction`
applies each update again on the table as it is (`applyUpdates`): the
cache is empty, the delete manifests are written again, and every delete
file is added to the summary a second time. The snapshot says it added
twice the delete files, bytes and records it did, and its totals carry the
excess to every later snapshot. The manifests are right.

A row delta retried outside a transaction (the producer's own retry
loop) runs `cleanUncommitted` only once its commit has succeeded, so it
counts once.

## Reproduction

On `InMemoryCatalog`, format 2:

1. a table with `commit.manifest.min-count-to-merge` = 2, one data file and
   one equality delete file (one delete manifest);
2. a transaction adds another equality delete file (a row delta);
3. another writer creates a branch;
4. the transaction commits (it retries once).

The transaction's snapshot says `added-delete-files` = 2,
`added-files-size` = 20 and `total-delete-files` = 3; it added one file of
10 bytes, and the table has two. With merging off, or without the race, it
says 1, 10 and 2.

## Cause

`MergingSnapshotProducer.newDeleteFilesAsManifests` (1.12.0):

```java
if (hasNewDeleteFiles && !cachedNewDeleteManifests.isEmpty()) {
  ... // delete the cached manifests
  cachedNewDeleteManifests.clear();
  addedDeleteFilesSummary.clear();       // only here
}
if (cachedNewDeleteManifests.isEmpty()) {
  ...
  deleteFiles.forEach(file -> addedDeleteFilesSummary.addedFile(spec, file));
  ... // write the manifests
}
```

`cleanUncommittedAppends` empties `cachedNewDeleteManifests` (it deletes
and clears what the committed snapshot does not hold), so the second
branch runs again with the summary as the first left it.

## Fix

Clear the summary where the manifests are written, whatever emptied the
cache (#17986's change). The data side keeps its summary from the time
files are added, so it needs nothing.

## Tests

`TestTransaction.testTransactionRetryCountsItsDeleteFilesOnce` (format
versions 2 to 4): the reproduction's steps; it fails before the fix (2
added delete files, 3 in total), and passes after. `TestTransaction` (104)
and `TestRowDelta` (372) pass.

## Before a PR

#17986 carries the fix with a larger change (rewrite manifests committed
one at a time); the transaction's path could be offered there as a second
test, or alone as a one-line change with this test.

## In fileio-catalog

Canary `TestIcebergCoreIssues.aRetriedTransactionCountsItsDeleteFilesOnce`.
The rebase oracle compares snapshot summaries: before the fix, a table
transaction R that the subject merged and the reference retried differed
there.
