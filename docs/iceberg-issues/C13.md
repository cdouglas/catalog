| | |

| **Found by** | fileio-catalog's `TestCatalogFaultProperties`, 2026-10-20, at try 3,172 of a 30,000-try run of `faultyStorageNeverMisreportsACommit`: an expiry whose commit landed failed with `UncheckedIOException` when reading the catalog back failed, and the property counts an operation that fails, other than with `CommitStateUnknownException`, as one that did not take effect. ## Summary

`ExpireSnapshots.commit()` commits, then cleans up the files of the
snapshots it expired: it reads the table back, works out which files no
remaining snapshot reaches, and deletes them. If reading the table back
fails, or the reachable cleanup cannot read a manifest list, the
exception escapes `commit()`. The caller is told the expiry failed,
though it committed.

## Reproduction

```java
// table operations whose refresh fails once a commit has gone through
TableOperations ops = new ForwardingOps(table) {
  boolean committed = false;
  public void commit(TableMetadata base, TableMetadata metadata) {
    super.commit(base, metadata);
    committed = true;
  }
  public TableMetadata refresh() {
    if (committed) throw new UncheckedIOException(new IOException("refresh failed"));
    return super.refresh();
  }
};

new BaseTable(ops, "t").expireSnapshots().expireOlderThan(now).commit();
// UncheckedIOException: refresh failed -- but the snapshots are gone
```

## Cause

`commit()` runs the cleanup after the commit loop, outside any handler
([RemoveSnapshots.java#L360-L380](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/RemoveSnapshots.java#L360-L380)).
`cleanExpiredSnapshots` starts with `ops.refresh()`
([#L388-L389](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/RemoveSnapshots.java#L388-L389)),
and `ReachableFileCleanup` rethrows a failure to read a snapshot's
manifest list
([ReachableFileCleanup.java#L118](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/ReachableFileCleanup.java#L118),
[#L149](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/ReachableFileCleanup.java#L149)),
though it logs a failure to list the reachable files
([#L224](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/ReachableFileCleanup.java#L224)).
`SnapshotProducer` handles the same situation by logging "Failed to load
committed table metadata or during cleanup, skipping further cleanup"
([SnapshotProducer.java#L572](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/SnapshotProducer.java#L572)).

## Impact

`PendingUpdate.commit()` reports a failure that is not
`CommitStateUnknownException` to say the update did not commit, and
callers act on that:

- a job that retries the expiry finds nothing more to expire, so the
  files of the snapshots the first attempt expired are never deleted;
- a caller that records the failure, or alerts on it, reports an expiry
  that happened as one that did not.

Nothing is corrupted: the cleanup either did not start or deleted only
files nothing reaches.

## Fix

`cleanExpiredSnapshots` logs a failure to read the table back, and a
failure of the cleanup itself, and skips the cleanup:

```java
// The expiry has committed: a cleanup that cannot run leaves files behind, and the expiry stands
TableMetadata current;
try {
  current = ops.refresh();
} catch (RuntimeException e) {
  LOG.warn("Failed to refresh the table after expiring snapshots, skipping file cleanup", e);
  return;
}
...
try {
  cleanupStrategy.cleanFiles(base, current, cleanupLevel);
} catch (RuntimeException e) {
  LOG.warn("Failed to clean up the files of expired snapshots", e);
}
```

The checks between the two, that an incremental cleanup the caller asked
for can run, still throw `UnsupportedOperationException`, as
`TestRemoveSnapshots` expects.

## Tests

In `TestRemoveSnapshots`, on every format version:

- `testCommittedExpiryWhoseRefreshFails`: the reproduction, with
  incremental cleanup and without. The expiry returns normally, and the
  table has one snapshot.
- `testCommittedExpiryWhoseCleanupFails`: reading a manifest list fails
  once the expiry has committed, with reachable cleanup (incremental
  cleanup already logs such failures). The expiry returns normally.

All 12 cases that run fail on 1.12.0. With the fix, `TestRemoveSnapshots`
(576 cases) and the full `iceberg-core` test task pass.

## Before a PR

- **The incremental-cleanup checks.** `validateCleanupCanBeIncremental`
  also throws after the commit, when the caller asked for an incremental
  cleanup that cannot run. Upstream's tests expect that exception, so the
  fix keeps it, but it has the same flaw: the expiry committed. Checking
  before the commit, on the metadata the attempt commits, would fix both;
  that changes when those tests' expiries commit.
- **Logging.** Two warnings are new. A reviewer may prefer one, or a
  metric of skipped cleanups.

## In fileio-catalog

No workaround. Before fileio-catalog's fuzzer could remove refs with an
expiry, an expiry changed nothing its model compares, so the property
could not tell that one had taken effect. The canary is
`TestIcebergCoreIssues.anExpiryThatCommittedDoesNotFailOnItsCleanup`. It
asserts only that an expiry whose commit went through does not throw
when reading the table back fails.
