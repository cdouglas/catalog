# C18. A replace of partitions, an overwrite checking its filter, or a merge of appended manifests fails with an NPE on a removed spec

| | |
|---|---|
| **Affects** | Iceberg 1.12.0, and `main` at `834441b96` (2026-10-21), on every catalog. 1.8.0 added the spec removal (`ExpireSnapshots.cleanExpiredMetadata`). |
| **Upstream** | Not reported (searched apache/iceberg's issues, PRs and PR branches, and the issues@ and dev@ lists, 2026-10-21). rdblue (member) anticipated the race in the review of [#10755](https://github.com/apache/iceberg/pull/10755), which added the removal: "A conflict here would require that a concurrent writer is using a spec other than the default or has changed the default spec. There's already a validation for the second case, `assert-default-spec-id`." The reproduction is that second case, in the order the validation doesn't cover: the default spec changed and the old spec was removed before the writer, still on the old spec, commits (C11). |
| **Fix** | [`4692c71`](https://github.com/cdouglas/iceberg/commit/4692c719a5a8d796fa99b62518839ea63ba58360) on [`core-fixes`](https://github.com/cdouglas/iceberg/tree/core-fixes), "Core: Fail cleanly on a removed spec in replace, overwrite and merge paths". 4 files, +89 -3. Builds on C11: cherry-picks onto `main` at `834441b96` after it. |
| **Found by** | fileio-catalog's review of Iceberg's commit retry paths for state read before an attempt, 2026-10-20, checking the paths C11 left. Reproduced in `TestReplacePartitions`, `TestOverwrite` and `TestMergeAppend`. |

## Summary

C11 makes a commit of files whose partition spec another writer removed
fail with `ValidationException`. Three paths look the spec up before
C11's checks, and fail with a `NullPointerException` instead:

- `ReplacePartitions`, which uses the added files' spec in its conflict
  validation and to replace all data of an unpartitioned table;
- `OverwriteFiles` with `validateAddedFilesMatchOverwriteFilter()`,
  which projects its filter through the files' spec;
- a merge append whose appended manifests are merged
  (`commit.manifest.min-count-to-merge`), which writes the merged
  manifest with the spec.

Nothing is committed: each fails before it could commit the files.

## Reproduction

```java
ReplacePartitions replace = table.newReplacePartitions().addFile(FILE_A);   // spec 0

Table other = catalog.loadTable(ID);                       // another writer
other.updateSpec().addField("id").commit();
other.expireSnapshots().cleanExpiredMetadata(true).commit();   // removes spec 0

replace.commit();
// NullPointerException: dataSpec() is null
```

## Cause

`MergingSnapshotProducer.dataSpec()` returns the spec of the added data
files, looked up in the table's current metadata without a check
([MergingSnapshotProducer.java#L154-L162](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/MergingSnapshotProducer.java#L154-L162),
[#L257-L259](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/MergingSnapshotProducer.java#L257-L259)).
`BaseReplacePartitions` calls it in `validate` and `apply`
([BaseReplacePartitions.java#L91](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/BaseReplacePartitions.java#L91),
[#L100](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/BaseReplacePartitions.java#L100),
[#L114](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/BaseReplacePartitions.java#L114)),
and `BaseOverwriteFiles` in `validate`
([BaseOverwriteFiles.java#L138](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/BaseOverwriteFiles.java#L138)).
The manifest merge managers look the spec up the same way
([MergingSnapshotProducer.java#L1282](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/MergingSnapshotProducer.java#L1282),
[#L1346](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/MergingSnapshotProducer.java#L1346))
to write a merged manifest
([ManifestMergeManager.java#L195](https://github.com/apache/iceberg/blob/apache-iceberg-1.12.0/core/src/main/java/org/apache/iceberg/ManifestMergeManager.java#L195)).
An appended manifest skips C11's lookup of the spec for new files, and
the merge runs before C11's check of the new snapshot's manifests.

## Impact

The commit fails with an exception that doesn't say what happened. The
table is unchanged. With C11, the same commits through the other paths
fail with `ValidationException`.

## Fix

`dataSpec()` and the merge managers look the spec up with C11's
`specForNewFiles`, which fails with `ValidationException` when the
metadata the attempt commits on lacks it:

```java
@Override
protected PartitionSpec spec(int specId) {
  return specForNewFiles(specId);
}
```

## Tests

On every format version, on `main` and on a branch:

- `TestReplacePartitions.testReplaceAfterConcurrentSpecRemoval` and
  `testReplaceWithValidationAfterConcurrentSpecRemoval`;
- `TestOverwrite.testOverwriteMatchingFilterAfterConcurrentSpecRemoval`;
- `TestMergeAppend.testMergeAppendedManifestsAfterConcurrentSpecRemoval`.

All 32 cases fail with a `NullPointerException` without the fix. With
it, those classes, `TestFastAppend`, `TestRowDelta`,
`TestOverwriteWithValidation` and the full `iceberg-core` test task
pass.

## Before a PR

- **Fold into C11's PR.** This finishes C11's fix, and needs its
  `specForNewFiles`. Upstream, one PR for both is simpler to review.

## In fileio-catalog

No workaround. `TableScript` replaces partitions, but no fuzzer removes
a spec under a pending replace. The canary is
`TestIcebergCoreIssues.aReplaceOfPartitionsOfARemovedSpecFailsCleanly`.
It asserts only that the replace does not fail with a
`NullPointerException`.
